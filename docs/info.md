## How it works

A signed INT8 dot product accelerator (N=8) with a parallel-pin ready/valid interface: one operand byte per clock in the order a0,b0,a1,b1,..., multiplied and accumulated as each pair arrives. All products are summed exactly, then a single 20-bit saturate is applied. The result can be read while the next vector streams in. The MAC is pipelined in three stages (operand pair register, multiply-accumulate, saturate), so the pin-to-result path never goes through the multiplier in one clock; the result appears two clocks later, throughput is unchanged. CHAIN (`uio[3]`) makes dot products of any length: if CHAIN is 1 when the last byte of a 8-pair vector is taken, no result is sent and the next vector keeps adding to the same 32-bit sum (no overflow up to 131,072 pairs); the result is saturated once, when a vector ends with CHAIN = 0. ABORT also discards a carried sum.

Design `b26e52f8-b8a4-4fb7-8a90-2c88880553d4` was verified in chip-lab against a fixed reference model and an RTL scoreboard, then wrapped for the Tiny Tapeout pinout.
Pre-layout sky130 standard cell area is 6334 um^2 and the selected tile size is 1x1 (estimate).

## How to test

Put a byte on `ui_in` and hold `uio[0]` (IN_VALID); it is taken on each rising clock edge where `uio[4]` (IN_READY) is 1. After 16 bytes the 3-byte result appears on `uo_out`, least significant byte first, sign extended: `uio[5]` (OUT_VALID) is 1 and each rising edge with `uio[2]` (OUT_READY) = 1 advances to the next byte. With both sides always ready one vector completes every 16 clocks. `uio[1]` (ABORT) discards a partial vector and sets `uio[7]` (ERR); `uio[6]` is BUSY. A fast host such as the RP2040 PIO is needed to keep up with one byte per clock.

`host/pin_client.py` is a MicroPython driver for the demo board (manual clocking, protocol check): copy it and `host/vectors.json` to the RP2040, enable the project, then `import json, pin_client; pin_client.main(**json.load(open('vectors.json')))`. The same driver runs against the RTL in the cocotb test.
